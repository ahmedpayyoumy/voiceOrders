================================================================================
  VOICE ORDERS — COMPLETE SYSTEM DOCUMENTATION
================================================================================

  A voice-to-order processing system with ElevenLabs real-time transcription,
  OpenAI correction/parsing, local order storage, webhook dispatch, and
  full Daftra ERP API integration.

  4. BUSINESS LOGIC FLOWS
================================================================================

  4.1 VOICE ORDER FLOW
  ────────────────────────────────────────────────────────────────────────────────

  1. User clicks microphone button
  2. Browser requests GET /api/elevenlabs/token
     → ElevenLabsController calls ElevenLabs API → returns ws_url + token
  3. Browser opens WebSocket to ElevenLabs real-time transcription
  4. User speaks → ElevenLabs sends partial transcripts (real-time display)
  5. On silence (VAD, 1.5s threshold) → committed transcript received
  6. Recording stops after 60s max or user click
  7. User can:
     a. Click "Suggest fix" → POST /api/transcript/suggest
        → OpenAI GPT-4o-mini corrects transcription errors
     b. Manually edit the transcript text
     c. Enter Daftra credentials (domain + API key)
     d. Click "Interpret" → POST /api/daftra/interpret
        → AI parses NL query into structured intent
     e. Click "Send Order" → POST /api/orders or /api/orders/daftra

  4.2 LOCAL ORDER CREATION (POST /api/orders)
  ────────────────────────────────────────────────────────────────────────────────

  1. Validate: { transcript: required|string }
  2. Check quota: if user.used_this_month >= user.monthly_quota → 429
  3. Create Order record (status: pending)
  4. Create UsageLog (action: transcription)
  5. Increment user.used_this_month
  6. Dispatch ProcessOrderWebhooks job (queued, database driver)
  7. Return order JSON (201)

  4.3 WEBHOOK DISPATCH (ProcessOrderWebhooks job)
  ────────────────────────────────────────────────────────────────────────────────

  1. Load user + active webhook endpoints
  2. If no endpoints → update order status to "sent", return
  3. For each endpoint:
     a. Build payload:
        - Base: { transcript, order_id, user_id, timestamp }
        - If endpoint has transform_prompt:
          → Call OpenAI GPT-4o-mini with prompt to parse transcript
          → Store parsed_data on order
          → Append parsed data to payload
     b. Send HTTP request (with custom headers, 15s timeout)
     c. Log success/error in responses array + UsageLog
  4. Update order: status = "sent", response_log = [responses]

  4.4 DAFTRA ORDER FLOW (POST /api/orders/daftra)
  ────────────────────────────────────────────────────────────────────────────────

  1. Validate: { transcript, daftra_domain, daftra_api_key }
  2. Check quota
  3. Call DaftraService::processVoiceOrder(transcript, apiKey, domain):
     a. Call OpenAI to parse transcript:
        → Extract: { client_name, items: [{item, quantity, unit_price}] }
     b. Create DaftraClient(domain, apiKey)
     c. Build InvoiceData with parsed items + client name + notes
     d. POST to https://{domain}.daftra.com/api2/invoices.json
        → Header: APIKEY: {apiKey}
        → Body: { Invoice: { client_business_name, notes },
                  InvoiceItem: [{ item, quantity, unit_price }] }
     e. Return Daftra response
  4. Create local Order record (status: sent, parsed_data, response_log)
  5. Create UsageLog (action: daftra_order)
  6. Increment quota
  7. Return order + parsed data + Daftra result

  4.5 NL QUERY INTERPRETATION (POST /api/daftra/interpret)
  ────────────────────────────────────────────────────────────────────────────────

  1. Validate: { transcript }
  2. Call DaftraService::interpretAndExecute(transcript):
     a. Call OpenAI with system prompt describing all 34 Daftra modules
     b. AI returns structured JSON:
        { type: "list"|"get"|"create"|"update"|"delete",
          module: "invoices"|"clients"|...,
          filters: { client_name: "...", date_from: "...", ... },
          is_complete: true|false,
          clarification: "..." }
     c. If not complete → return clarification question
     d. If Daftra credentials provided → execute against Daftra API
     e. Format response into natural language
  3. Return result to frontend

  4.6 QUOTA RESET (Scheduled Command)
  ────────────────────────────────────────────────────────────────────────────────

  1. Runs hourly via app:reset-user-quotas
  2. Find users where quota_reset_at <= now AND used_this_month > 0
  3. Set used_this_month = 0, quota_reset_at = null

  6.1 ARCHITECTURE
  ────────────────────────────────────────────────────────────────────────────────

  Usage:
    $client = new DaftraClient('my-domain', 'my-api-key');

    // Direct resource access (magic method)
    $client->invoices()->list(['client_id' => 42]);
    $client->clients()->get(1);
    $client->products()->create(new ProductData(name: 'Widget', price: 9.99));
    $client->suppliers()->update(5, new SupplierData(email: 'new@email.com'));
    $client->stock_transactions()->delete(10);

    // OR explicit module access
    $client->module('invoices')->list($query->toQueryParams());

    // High-level service
    $daftra = new DaftraService($client);
    $intent = $daftra->interpret("show invoices for Acme Corp");
    $result = $daftra->execute($intent);

  6.3 DAFTRA API SPECIFICATIONS
  ────────────────────────────────────────────────────────────────────────────────

  Base URL:     https://{subdomain}.daftra.com/api2/
  Auth Header:  APIKEY: {your-api-key}
  Content-Type: application/json

  Standard CRUD endpoints per module:
    GET    /{module}.json              List all (paginated)
    GET    /{module}/{id}.json         Get single
    POST   /{module}.json              Create new
    PUT    /{module}/{id}.json         Update existing
    DELETE /{module}/{id}.json         Delete

  Request body format (create/update):
    { "ModuleName": { field1: value1, field2: value2 },
      "RelatedItems": [{ item1 }, { item2 }] }

  Response format:
    { "code": 200|202,
      "result": "successful"|"failed",
      "id": 123,                    // Only on create
      "data": { "ModuleName": { ... } },
      "pagination": { "total": 100, "current_page": 1, "per_page": 20 } }

  Query parameters:
    limit       int     Items per page (1-1000, default 20)
    page        int     Page number
    client_id   int     Filter by client
    product_id  int     Filter by product
    supplier_id int     Filter by supplier
    store_id    int     Filter by store/warehouse
    staff_id    int     Filter by staff
    status      string  Filter by status
    date_from   string  Start date (Y-m-d)
    date_to     string  End date (Y-m-d)
    search      string  Text search

  11. RUNNING THE APPLICATION
================================================================================

  1. Database setup:
       php artisan migrate

  2. Build frontend:
       npm install && npm run build

  3. Start queue worker (for webhook dispatch):
       php artisan queue:work

  4. Start dev server:
       php artisan serve

  5. Schedule (for quota resets):
       php artisan schedule:work
       OR add to crontab: * * * * * php /path/to/artisan schedule:run >> /dev/null 2>&1
